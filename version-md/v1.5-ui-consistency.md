## §1 卡片底色：从「描边双保险」到「明暗分色 + tonal 对比」(1.5.14~16)

用户反馈逐步驱动的三步收口：

1. **深色卡片对比不明显、看不出弧度** → 首版给卡片加 `surfaceContainerHigh` 底 + 1dp `outlineVariant`
   外描边（1.5.14）。
2. **「描边太刻意（标在外侧的明显边框）」** → 去描边，深色改靠 `surfaceContainerHigh`(N17) 与背景
   `surface`(N6) 的 ~11 级 tone 明度差**自然浮出**——这才是 Material 深色正统的 tonal elevation，
   外描边是多余的双保险（1.5.15）。
3. **「浅色 `surfaceContainerHigh`(N92) 发灰、奇怪」** → **按明暗分色**：浅色回 `surfaceContainerLow`
   (N96，接近白、不发灰)，深色保持 High。抽 `cardContainerColor()` 一处统一（1.5.16）。

`components/GroupCard.kt`：

```kotlin
@Composable
fun cardContainerColor(): Color =
    if (LocalDarkTheme.current) MaterialTheme.colorScheme.surfaceContainerHigh
    else MaterialTheme.colorScheme.surfaceContainerLow
```

全 app 卡片（GroupCard / 首页 ElevatedCard / 规则 SectionCard）统一取此色。
**核心结论：区分卡片靠「明度对比」而非「描边」；且明/暗两侧的最优底色不同，必须分色。**

## §3 「卡片高度」不统一根因 + 全面一致性审查(1.5.18~19)

**根因**（用户观察「监控/设置卡片没有主页/规则的卡片高度」）：全 app 用了两套卡片组件——
主页/规则用 `ElevatedCard`（默认 ~1dp elevation，**有阴影浮起**）；监控/设置用 `GroupCard`，
底层是 `Column + background`（**纯色块、无阴影**）。浅色下卡片色 N96 与背景 N98 仅差 2 级 tone，
全靠阴影区分 → 无阴影的 GroupCard 显得扁平贴底。
**修**：`GroupCard` 改用 `ElevatedCard`，与主页/规则完全同款（同 elevation / 圆角 / 底色）（1.5.18）。

**全面审查**：3 个 agent 分头扫 `ui/`（① 卡片容器 ② 颜色 ③ 组件/间距/字体），合并去重后
按「用户可感知程度」分级，A+B+C 全修（1.5.19）：

- **A（一眼可见）**：规则集管理×2 / 帮助 / 引导 四卡深色底色未走 `cardContainerColor`（默认
  `surfaceContainerLow`，深色偏灰融背景）· 卡内竖向间距 8/6/4dp 混用 → 统一 8dp ·
  **PAC 降级告警首页红、监控橙**（同概念异色）→ 统一 `StatusColors.warn()` 橙 ·
  白名单域名行 `bodyMedium` 小一号 → `bodyLarge` · 新建规则集对话框 chip 未套统一选中色。
- **B（细看可辨）**：卡间距 12 vs 8dp → 12 · 卡内大数字 `titleLarge` vs `headlineSmall` → `titleLarge` ·
  列表行高 4/8/10dp → 数据行统一 8 · 网格圆圈 32/40/44dp → 图标格统一 40。
- **C（代码收敛）**：`error` 分支散用 `colorScheme.error`（应走 `StatusColors.bad()`，3 处）·
  冗余 `fontWeight = SemiBold`（titleMedium 本就是 SemiBold）· chip 选中色抽 `stdFilterChipColors()`。

## §4 共享组件重构 + 对抗验证(1.5.20~21)

抽 `components/SharedUi.kt`，消除各页手写重复：

| 组件 | 收敛来源 | 备注 |
|---|---|---|
| `CardGrid` | MonitorScreen 私有 → 公共 | 规则页手写 `descs.chunked(4)` 网格改用它，**顺带获得折叠** |
| `AvatarCircle` | GridCell(40) / DataRow(32) / RuleSetGridCell(40) | 圆形头像/图标容器 |
| `LabeledSwitchRow` | 设置项 / 规则组 / 可分享接口 | 三处同构（title bodyLarge + subtitle + Switch）；SettingsScreen 本地 `SwitchRow` 改为委托，调用点不变 |
| `ExpandCollapseButton` | 各页「展开全部 N / 收起」 | 整宽 TextButton |

> RuleSetManager 的 `UserRuleSetCard` / `BuiltinGroupCard` 标题带特殊字重、且是「开关行 + 按钮行」
> 复合卡，**有意保留**未收敛。

**workflow 5-verifier 对抗性验证**（行为等价性）：每个 verifier 独立 `git diff` 核对一个组件重构
前后的运行时语义。关键——**区分「批次1的有意视觉统一」与「批次2的重构回归」**：

- 两个 `equivalent=false` 经核查是有意统一（网格圆圈 44→40、设置开关标题 →bodyLarge），非回归。
- 揪出并修的真问题（1.5.21）：监控页 clients/domains 两处展开按钮**漏收敛** + 4 文件共 8 处
  **死 import** → 补齐 `ExpandCollapseButton` + 清理。

## 方法与验证

- 全程真机（Pixel Fold `36261FDHS000E2`，无线 adb）深/浅色逐页截图核对。切主题用 app 内「外观」chip
  ——app 外观固定浅/深时 `cmd uimode night` 不生效（LocalDarkTheme 读 app 设置而非系统）。
- 重构等价性用 workflow fan-out 5 个 verifier 独立审查，**避免把批次1的有意改动误判为重构 bug**——
  单靠 build 通过无法区分「行为等价」与「有意的行为变更」。
- 踩坑：Pixel Fold 折叠态活跃 display id 会在外屏/内屏间切换，截图需对当前活跃屏用 `screencap` 写文件
  （`exec-out` 会把多屏告警文本混入 PNG）。
