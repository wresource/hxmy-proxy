# hxmy proxy 1.49.68

本版在 1.49.26 基础上扩展代理协议、改善直连双栈建连与 DNS 调度，并增加默认关闭的局域网目标代理开关。原有 HTTP、SOCKS5 TCP、规则、流量查看和出口设置继续保留。

## 协议与连接

- 新增 HTTP/1.1 CONNECT-UDP 和原生 SOCKS5 UDP ASSOCIATE，让支持这些接口的客户端转发 UDP。保留规则、认证、接入限制、出口选择和流量统计；停止共享会回收所属连接与后台工作。
- 新增有界 SOCKS5 BIND，以及手机网络 DNS 报文和 IPv4/IPv6 Echo 接口。BIND 用于支持该协议的二次连接，例如主动 FTP；对端必须能访问手机返回的监听地址，不能绕过运营商 NAT 或 VPN 的入站限制。
- DIRECT TCP 建连尊重物理网络的首选地址族，交错尝试 IPv6/IPv4，并保留原有备用候选。UDP 保持兼容的域名地址选择，IPv6 字面量及仅有 AAAA 答案的目标继续支持。
- 改进 DNS 主路交接、DoH 调度及取消回收，减少慢查询阻塞后续解析的情况。指定物理出口、有效缓存、已有恢复语义与连接总预算继续保留。

## 局域网目标

- 在 **设置 → 隐私 → 隐私与安全** 增加“**允许代理局域网目标**”，默认关闭。旧版本没有明确选择时也保持关闭；明确选择可以保存、备份和恢复。
- 关闭时，PAC 让客户端直连内网 IP、简单主机名（如 `nas`）、`.local` 和 `.home.arpa`。仍被客户端强制发送到手机的本地目标请求会被拒绝，并提示配置客户端直连。
- 开关控制最终访问目标，不妨碍电脑等设备通过局域网连接手机代理。确实需要手机代为访问内网时可以开启；回环和链路本地出口仍不转发。
- 可选配套客户端可以读取 App 已生效的策略。App 是设置来源，不要求安装 Mac 配套，也不会因新增协议自动接管电脑全部流量。

## 使用与验证

- 常规 HTTP/SOCKS5 TCP 客户端沿用原接入方式；UDP、BIND 和控制接口需要兼容客户端。支持这些接口不代表所有应用的 QUIC/WebRTC 都会自动经过代理。详细格式与限制见[协议说明](../protocol/udp-proxy.md)。
- App 仍是普通 Android 代理服务，**不要求 root、不新增 VpnService、不替换用户已有 VPN**。
- Android 10 及以上，包名 `com.mzstd.hxmyproxy`，versionCode **308**。APK 用于直接安装；同签名覆盖更新可保留数据。AAB 用于 Google Play 提交，本次 GitHub 发布不代表已提交或上线 Play。
- 发布沿用 308 的既有验收：809 项 JVM 测试、5 项 Android 原生回归、119 项 PAC JavaScript 检查通过；Release R8 和 Lint 通过（0 错误、25 条警告）。发布时重新构建 APK/AAB，并核对代码、资源及 R8 映射与已验收 308 一致；构建提交信息更新为已提交的源码版本。
- Pixel Fold 和 Pixel Tablet 已完成保留数据的 308 更新与启动核对。阶段性协议测试不等同所有 VPN、网络和多日运行验证，也不承诺所有网页达到固定性能比例。

## English

- Add HTTP/1.1 CONNECT-UDP, native SOCKS5 UDP, bounded SOCKS5 BIND, phone-network DNS messages and IPv4/IPv6 Echo interfaces. Compatible clients are required; incoming BIND connections still depend on network reachability.
- Improve DIRECT TCP dual-stack selection by respecting the physical network's first address family, alternating IPv6/IPv4 candidates and preserving fallback. Keep compatible UDP address selection.
- Improve DNS handoff, DoH scheduling and cancellation handling while preserving selected networks, healthy caching and recovery behavior.
- Add **Allow local network targets**, off by default. PAC bypasses private addresses and local names; local requests still sent to the phone receive client-side bypass guidance. Explicit choices survive backup and restore.
- Keep the Android app as the policy source. No root, additional VPN service or automatic system-wide traffic capture is required.
- Reuse the validated 308 source and verify rebuilt release payloads and mapping. APK is for installation; AAB is for Play submission. This GitHub release does not publish to Google Play or certify every VPN/network combination.
