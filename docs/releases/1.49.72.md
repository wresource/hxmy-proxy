# hxmy proxy 1.49.72

本版在 1.49.68 基础上增加客户端全部直连与域名后缀规则，改善规则列表交互，并加固 DNS、出口健康判定和长连接转发。

## 新功能与交互

- 在客户端详情中开启“全部直连”，让该来源 IP 的请求统一使用手机 **Direct egress**。请求仍经过手机，不会替客户端关闭系统代理或改为客户端本机出网。此模式覆盖该客户端的域名路由与拦截规则，保留认证、准入、出口和局域网目标保护；关闭后恢复原规则。
- 支持 `.cn` 等域名后缀规则，包括多层子域、手动添加、导入、编辑及备份恢复；原有规则例外和优先级保留。
- 改善添加、编辑和刷新规则时的列表跳动，保留分页位置并避免过期异步结果覆盖当前页面。

## 稳定性与兼容性

- 串行处理同一 DNS 查询的回调，校验并快照化地址结果，避免无效数据进入连接候选；连接异常记录明确的失败终态。
- 连接失败后可对系统 DNS 结果进行有界新鲜查询，保持共享缓存、查询额度和取消规则；相同答案不再误续旧缓存有效期或改变来源。
- 将真实业务连接成功反馈给对应出口的健康状态，防止旧失败探针覆盖较新的成功证据；补充 IPv6 探测，保留原隔离与复检机制。
- 双向转发按连接整体活动判定空闲，避免持续单向传输被另一方向的读超时打断；保留半关闭、背压和真正空闲时的回收，并补充关闭诊断。
- 新增可选客户端路由能力，按实际来源 IP 提供 App 已生效的模式、会话和修订号。配套客户端可正确识别“全部直连”；旧客户端与原有认证、局域网策略继续兼容。

[Mac 配套 2026.11.08.1](https://github.com/wresource/proxyshim/releases/tag/2026.11.08.1-companion)同步支持客户端意图，并修复发现等待和旧透明转发的半关闭问题。Mac 配套是可选组件，Android 不新增 VpnService 或 root 要求，局域网目标代理仍默认关闭。

## English

- Add per-client **All direct** mode, keyed by source IP. Traffic still passes through the phone's Direct egress; this does not disable the client's proxy. It overrides that client's domain routing and blocking rules while preserving authentication, admission and local-target safeguards. Turning it off restores normal rules.
- Support suffix rules such as `.cn`, including subdomains, import, editing and backup restore. Stabilize rule lists, pagination and editing during refreshes.
- Harden DNS callback serialization, address validation, bounded fresh DNS recovery and failure diagnostics without clearing the shared system cache.
- Feed successful business connections into network health recovery so stale failed probes cannot override newer success. Preserve isolation/recheck safeguards and add IPv6 probes.
- Fix idle handling for continuously active one-way transfers while preserving half-close, backpressure and cancellation.
- Expose optional, applied per-client routing intent for compatible companions. Existing proxy clients, authentication and local-network policy remain compatible.

Validation: 865 JVM tests, 10 Android native regressions, Release/R8 and Lint (0 errors, 10 existing warnings). APK and AAB are formally signed; Google Play rollout is separate. Real network switching and long-running application behavior still require observation.
