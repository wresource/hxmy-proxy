# hxmy proxy 1.49.26

本版在1.49.22基础上改善DNS故障恢复、Android双向转发兼容性和连接诊断。

## DNS与建连恢复

- 当备用解析地址全部超时或不可达时，允许在原连接预算内有限重查主DNS。同一上下文的并发请求共享解析恢复，避免持续复用不可用答案或发起重复查询风暴。
- 保留正常缓存、有效备用答案和慢而有效的主解析；单个地址失败、端口拒绝或取消不会一概清空域名缓存。旧请求的反馈不能覆盖新网络或新答案，缓存命中与连接成功不延长原有效期。
- DoH服务错开启动，结果仍遵守原优先级与地址族策略。共享3秒总预算和4个实际工作线程，队列有界；取消后仍阻塞的底层读取不会导致额外线程增长。
- NIO绑定回退与DNS恢复共用原建连截止时间，保留Direct、Strict和Degrade的出口语义；有可用替代出口时，原降级路径优先使用剩余时间。已发送的业务请求不会因这项恢复被重放。

## 双向转发与诊断

- 修复Android阻塞回退中，channel-backed socket的读取等待可能挡住反向写入、造成已连接却收不到回复的问题。保留普通绑定socket、半关闭排空、空闲回收及连接准入；独立等待资源随连接释放。
- 区分方向EOF、读写异常、主动停止、空闲回收和内部计量错误，保留首个终止原因与清理信息；已传输字节不再掩盖真实I/O失败，停止时的关闭异常不会误报网络失败。
- 增加解析答案身份、恢复阶段和真实连接地址/端口等诊断元数据，继续遵守日志开关；不记录TLS正文、认证头或模型请求内容。
- 本版不更改规则格式、导入分页或访问页筛选，也不保证消除远端服务主动关闭WebSocket的情况。

## English

- Recover from unreachable backup DNS answers with a bounded, shared primary recheck. Preserve healthy caching, slow valid primary results, successful rescue answers and network-generation isolation.
- Stagger DoH providers without changing answer priority. Keep one total deadline, four actual workers and a bounded queue, including when native reads ignore cancellation.
- Share the original connection deadline across DNS recovery and NIO binding fallback. Preserve Direct/Strict/Degrade routing and the existing alternate-egress opportunity; never replay an established request.
- Fix Android blocking fallback where a waiting channel-backed reader could prevent reverse writes. Preserve half-close, idle cleanup, byte delivery and connection ownership.
- Improve close-cause and connection metadata. Distinguish I/O failure from cancellation and internal accounting errors without logging encrypted payloads or credentials.
- 679 JVM tests and 34 Android checks passed; Release R8 and Release Lint passed. Validation used an API37 emulator and controlled VPN, not every device or multi-day production traffic. Remote WebSocket closures may still occur.
